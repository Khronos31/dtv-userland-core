# DTV userland common core

This repository contains portable C++17 increments of shared DTV userland code. It provides the error/result, logging, mock transport foundation, a bounded UDTV 1.0 wire subset, and optional internal receiver/card ownership engines. It is not a daemon, hardware transport, complete wire protocol, smart-card protocol, or card hardware implementation.

The static libraries are `dtv::core`, `dtv::wire`, `dtv::identity`, `dtv::tuning`, and `dtv::json`. Consumers can use the installed CMake package with `find_package(dtv_userland_core CONFIG REQUIRED)`. The wire library links the core library, identity links core, tuning links wire, and JSON links wire. These targets compile without exceptions or RTTI and have no operating-system or USB dependency.

Configure with CMake and enable `BUILD_TESTING` to build the standalone foundation and wire tests. The optional `DTV_LEGACY_SOURCE` cache path enables the behavioral equivalence check against a fixed PX4 source checkout. See `PROVENANCE.json` for the source pin, extracted-file hashes, per-file source/destination SPDX identifiers, moved ranges, and exclusions.

The optional static library `dtv::receiver` (CMake option `DTV_USERLAND_BUILD_RECEIVER`, default off; consumers that need it enable it explicitly) contains an internal compatibility engine for receiver leases, tuning, and stream attachment in `dtv/userland/detail/receiver_engine.h`. It is the PX4 TunerService lifecycle moved behind neutral types, so that product facades share one implementation; it is not the adopted v1 receiver contract and not a stable API. Tune timing starts after the receiver and power preparation exactly as before, so it does not enforce an end-to-end deadline, and frequencies are kHz. Receiver IDs are u16 identities independent of the eight-slot table. The receiver set is fixed when the engine is constructed; the supported consumers (the PX4 Q3U4, W3U4, MLT, and single-receiver backends, and ASICEN after its profile selection) have fixed receiver counts for the life of the service. Receivers that appear or disappear later are not supported by this increment. Only this target links Threads; installed consumers request it with `find_package(dtv_userland_core CONFIG REQUIRED COMPONENTS receiver)`.

The optional `dtv::card` interface target (CMake option `DTV_USERLAND_BUILD_CARD`, default off) exposes the internal `detail::CardOwnershipEngine<AtrSnapshot>` in `card_ownership_engine.h` and its template implementation. It carries the existing serialized ownership, sharing, presence/generation, transaction, and cleanup behavior behind neutral byte/session/backend seams. ATR snapshots are opaque values; product `CardAtr`, native protocol sessions, ATR parsing, T=1, IPC enums, and hardware code stay in their separately licensed product facade. The engine has no Threads, USB, or operating-system dependency and is not a public v1 card/deadline/multiple-reader contract. Installed consumers request it with `find_package(dtv_userland_core CONFIG REQUIRED COMPONENTS card)`.

The typed wire payload API includes HELLO, ACQUIRE, LIST/STATUS, tune and stream operations, events, and card/transaction records, alongside the bounded UDTV 1.0 envelope and frame handling. [Typed record documentation](docs/wire-records.md) separates byte syntax from complete context validation; callers must validate snapshots before publishing them. The original framing subset is described in [docs/wire-subset.md](docs/wire-subset.md). Connection state, dispatch, timers, sockets, JSON parsing, CLI translation and product endpoint migration remain outside this library increment. No current product client or daemon is wired to the new wire API.

The static library `dtv::identity` implements the adopted portable identity codecs: the `serial:`/`usb:` device selector grammar, connection instance canonicalization and reserved-name validation, the exact-span LANGID/USB string descriptor decoders (strict UTF-16LE to lossless UTF-8), and the versioned `DTVI` auto-identity encoding with `auto-` SHA-256-prefixed instances. It is pure and bounded, never allocates and never touches USB/OS state; physical discovery, serial trust/uniqueness, permissions/ACL and USB FD ownership stay in the OS adapters. The one mechanically transferred part is the neutral SHA-256 class in `dtv/userland/detail/sha256.h`; all other code is new. See [docs/identity.md](docs/identity.md).

The portable STATUS JSON exporter in `dtv::json` exposes `status_json_size` and `encode_status_json`. Each call validates the complete `StatusResponse` against its canonical `StatusContext`; the caller owns output storage. The size operation reports the exact compact UTF-8 length including the final newline. Encoding returns `BUFFER_TOO_SMALL` without changing the output when capacity is short. JSON size is limited by the record bounds and `size_t`, not by the wire control-payload cap. This library does not add a JSON parser or product endpoint.

The portable `dtv::tuning` helper resolves adopted channel or typed-Hz inputs into a wire system, requested Hz, and wire selection. Its grammar and boundaries are documented in [docs/tuning.md](docs/tuning.md). It preserves requested Hz and does not implement option parsing, device capability checks, backend quantization, or a product CLI cutover.
